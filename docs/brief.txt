Tu es responsable de la conception UX/UI, de l’architecture produit, du développement full-stack, de la base de données et de la mise en place d’une plateforme web complète de football à 5 entre amis.

Je vais joindre à cette demande :
- un moodboard
- un logo
- une palette de couleurs

Analyse ces références AVANT de concevoir l’interface.

Le moodboard, le logo, la palette et les règles de direction artistique décrites ci-dessous constituent la source de vérité visuelle du projet.

Ne crée pas une identité visuelle générique de SaaS ou une interface “IA” standard si cela contredit mes références.

==================================================
1. OBJECTIF DU PROJET
==================================================

Je veux créer une vraie plateforme web pour gérer nos matchs de football à 5 entre amis.

Ce n’est PAS un simple site vitrine.

Je veux un produit réellement fonctionnel permettant de :

- créer et gérer des joueurs
- créer des saisons
- créer et gérer des matchs
- gérer les participants à chaque match
- générer les équipes grâce à plusieurs systèmes de draft
- enregistrer les scores
- enregistrer les statistiques individuelles
- afficher les statistiques de chaque match
- afficher les statistiques cumulées des joueurs
- afficher des statistiques par saison
- créer automatiquement des classements
- créer automatiquement des facts / insights
- afficher les vidéos YouTube des matchs
- suivre les performances des joueurs
- calculer un ELO
- générer des radars de performance
- conserver l’historique des saisons
- ajouter les matchs au calendrier personnel
- administrer entièrement le site depuis une interface web

PRINCIPE CENTRAL :

“UNE SEULE SAISIE → PLUSIEURS CONSÉQUENCES AUTOMATIQUES.”

Si une statistique est modifiée dans un match, tout ce qui en dépend doit se recalculer automatiquement :

Match
→ Profil joueur
→ Saison
→ Classements
→ Radar
→ Facts
→ Records
→ Dashboard

Je ne veux jamais saisir deux fois la même donnée.

==================================================
2. CONTRAINTE ABSOLUE : ADMINISTRATION SANS CODE
==================================================

Une fois le site développé et déployé, je ne dois JAMAIS avoir besoin de modifier le code pour l’utiliser normalement.

Créer un véritable back-office sécurisé.

Depuis le site, un administrateur doit pouvoir :

- ajouter un joueur
- modifier un joueur
- archiver un joueur
- changer sa photo
- modifier ses informations
- modifier ses caractéristiques utilisées pour le draft
- ajouter des fun facts
- créer une saison
- modifier une saison
- terminer / archiver une saison
- créer un match
- modifier un match
- sélectionner les participants
- modifier date / heure / lieu
- lancer un draft
- modifier les équipes
- entrer un résultat
- entrer les statistiques
- corriger des statistiques
- ajouter des événements
- corriger la timeline
- choisir le MVP
- ajouter une vidéo YouTube
- définir le joueur de la saison
- gérer la récompense de fin de saison

Quand un nouveau joueur est ajouté, son profil doit apparaître automatiquement.

Quand une nouvelle saison est créée, toutes les pages et statistiques correspondantes doivent fonctionner automatiquement.

Aucune page joueur ou saison ne doit être codée individuellement.

------------------------------------------
RÈGLE COULEUR : 60 / 30 / 10
------------------------------------------

La répartition visuelle des couleurs doit suivre approximativement la règle :

60 % NOIR
30 % BLANC
10 % VERT

Cette règle doit guider l’ensemble du design system.

-------------------------
60 % — NOIR
-------------------------

Le noir est la couleur dominante.

Il doit surtout servir à :

- fonds principaux
- navigation
- grandes surfaces
- arrière-plans
- cartes
- sections
- panneaux statistiques
- modals
- menus

Je veux beaucoup de contraste.

L’interface doit être majoritairement sombre.

Le noir doit donner une impression :

- premium
- sportive
- moderne
- forte
- immersive

Éviter cependant un site totalement plat.

Créer de la profondeur grâce à :

- plusieurs nuances très proches de noir
- bordures légères
- variations de luminosité
- surfaces légèrement différenciées
- séparateurs
- ombres très discrètes si pertinentes

Ne pas introduire d’autres couleurs importantes simplement pour créer de la profondeur.

-------------------------
30 % — BLANC
-------------------------

Le blanc est principalement utilisé pour l’information.

Utilisations :

- textes
- titres
- chiffres
- statistiques
- labels
- icônes
- informations principales
- éléments graphiques nécessitant de la lisibilité

Créer une hiérarchie avec plusieurs niveaux :

BLANC PUR
→ données importantes
→ titres
→ score
→ chiffres clés

BLANC / GRIS CLAIR
→ informations secondaires

GRIS PLUS DISCRET
→ métadonnées
→ dates
→ labels secondaires

Je veux un contraste fort texte / fond.

Les informations importantes doivent être immédiatement lisibles.

-------------------------
10 % — VERT
-------------------------

Le vert est la couleur d’accent principale.

Il doit rester minoritaire pour conserver sa force visuelle.

Utiliser le vert principalement pour :

- boutons principaux
- CTA
- éléments actifs
- onglets sélectionnés
- highlights
- accents
- éléments décoratifs
- interactions importantes
- progression
- éléments positifs
- graphiques
- détails du radar
- sélection
- focus
- hover lorsque pertinent

Le vert ne doit PAS envahir les écrans.

Si tout est vert, plus rien n’est mis en valeur.

Le vert doit attirer naturellement le regard vers les éléments importants.

Utiliser précisément la nuance de vert fournie dans la palette que je joins.

------------------------------------------
HIÉRARCHIE VISUELLE
------------------------------------------

Le principe général doit donc être :

NOIR
= structure / environnement

BLANC
= information

VERT
= action / accent / attention

Exemple :

Fond noir
+
statistiques blanches
+
CTA vert

C’est cette logique qui doit dominer toute l’application.

Ne pas utiliser arbitrairement :

- bleu
- violet
- orange
- rouge
- jaune

comme couleurs principales.

Une couleur fonctionnelle ponctuelle peut être utilisée si réellement nécessaire pour des états comme erreur / alerte / carton, mais elle ne doit jamais devenir une couleur de branding concurrente au vert.
